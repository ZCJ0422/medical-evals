# Medical Evals 内部评测工作台设计规格

## 1. 目标与范围

为 `medical-evals` 提供一个面向内部测评团队的 Web 工作台。用户通过固定测试账号登录，配置被测模型和独立 Judge Model，选择平台内置数据集及版本，创建异步评测任务，并查看受题库保护的结果与单任务报告。

第一版按单机内网部署设计，但通过 API、存储、队列和 Provider 接口为未来多机器、多 Worker 和外部数据库迁移预留边界。

本规格覆盖：

- 内部固定测试账号和单一管理员权限；
- 模型 Provider 与模型配置；
- 平台内置数据集、数据集版本和内置 Rubric；
- 单模型异步评测任务；
- 进度、失败和自动重试；
- 结果、HTML/PDF 报告和题库保护；
- 前后端分离的 MVP 架构。

第一版不包含真实用户注册、邀请、SSO/LDAP、用户上传数据集、自定义 Rubric、多任务对比报告、自动清理或审计日志。

## 2. 用户与权限

第一版使用固定测试账号，不实现公开注册、邀请或 SSO。第一版只有一个管理员角色；后续如果团队规模扩大，再引入评测人员和只读查看者。

| 角色 | 能力 |
| --- | --- |
| 管理员 | 管理模型 Provider、模型配置、数据集版本、内置 Rubric 和固定测试账号；创建、运行、取消、删除评测；查看完整基准样本、标准答案和完整 Rubric；查看、生成、下载报告 |

权限必须在 API 层执行，不能只依赖前端隐藏按钮。虽然第一版只有管理员，平台基准集的完整样本数据仍不得出现在公开 API 响应、浏览器状态、公开 URL 或前端构建产物中。

第一版暂不记录管理员查看原始样本的审计日志，但代码边界应保留后续增加审计事件的空间。

## 3. 核心用户流程

### 3.1 创建并运行评测

```text
登录
  ↓
进入工作台
  ↓
创建评测任务
  ↓
选择一个 Provider 下的一个被测模型配置
  ↓
选择一个平台内置数据集及版本
  ↓
系统自动绑定对应的内置 Rubric
  ↓
选择一个独立 Judge Model 配置
  ↓
配置生成参数、并发、超时和重试策略
  ↓
执行 Preflight 检查
  ↓
创建异步任务并返回 task_id
  ↓
查看进度和最终结果
```

一次任务只评测一个被测模型。多模型比较通过创建多个任务实现；第一版不提供批量比较任务和横向对比报告。

### 3.2 Preflight 检查

启动前必须检查：

- 被测模型配置存在且凭据可用；
- Judge Model 配置存在且与当前 Rubric 兼容；
- Provider、模型、Endpoint 和请求格式可用；
- 数据集版本和内置 Rubric 可用；
- 参数值合法；
- 预计样本量、Token 和成本可计算时显示估算；
- 当前单机队列可接受任务。

认证失败、参数错误、数据版本缺失和不兼容错误必须在启动前阻止任务；网络超时、限流和临时服务错误由 Worker 处理重试。

## 4. 页面与导航

```text
登录页
  ↓
工作台首页
  ├── 评测任务列表
  ├── 创建评测
  ├── 任务详情与进度
  ├── 评测结果
  ├── 报告
  └── 系统管理（管理员）
      ├── Provider / 模型配置
      ├── 数据集与版本
      ├── 内置 Rubric
      └── 固定测试账号
```

### 4.1 工作台首页

展示最近任务、运行中任务、成功率、最近完成的评测和快捷入口。首页只显示聚合指标，不展示平台基准题目。

### 4.2 评测任务列表

支持按状态、模型、数据集、创建人和时间筛选。列表字段包括任务名称、被测模型、Judge Model、数据集版本、状态、进度、创建时间和完成时间。

### 4.3 创建评测页

采用分段表单：模型配置、数据集与 Rubric、Judge Model、运行参数、预检确认。数据集选择器展示名称、版本、领域、语言、样本数量和授权说明，但不展示题目内容。

### 4.4 任务详情页

显示任务状态、已完成样本数/总样本数、百分比、预计剩余时间（可计算时）、成功/失败/重试数量和错误摘要。第一版不展示逐条实时日志，避免侧面泄漏题库内容。

运行中的任务可由管理员取消。已取消任务不可继续运行；如需重跑，创建新任务。

### 4.5 结果页

分为三层：

1. **总览**：总分、分维度得分、通过率、安全性指标、平均耗时、Token、成本和样本完成情况；
2. **错误分析**：错误类型数量和比例、分数分布、失败/重试统计、脱敏后的摘要；
3. **样本审阅**：管理员可通过受保护接口访问完整原始样本；普通结果接口只返回聚合、错误类别和必要的脱敏信息。

## 5. 题库保护与数据边界

平台内置基准集是受保护资产。默认规则如下：

```text
普通 API 响应：不包含原题、标准答案、完整 Rubric
普通结果接口：只返回聚合结果、错误分类和脱敏信息
管理员：通过受保护接口查看完整样本
```

实现约束：

- 基准题目和标准答案只在后端评测 Worker 或管理员受保护接口中读取；
- 前端不接收完整题库，不把题目放入公开 API、URL、localStorage 或静态资源；
- 结果默认只保存必要的聚合指标和运行元数据；
- 是否保存模型完整回答由后端存储策略控制；完整回答只允许通过管理员受保护接口访问；
- 报告中不得包含未授权原题、标准答案或完整 Rubric；
- 管理员查看完整样本必须经过后端角色校验；
- 真实患者隐私数据不在第一版数据集范围内，系统文案应提醒内部用户避免接入未脱敏数据。

## 6. 任务状态与执行

任务状态至少包括：

- `queued`：已创建，等待 Worker；
- `running`：正在执行；
- `completed`：全部可处理样本完成；
- `partial_failed`：任务结束，但存在不可恢复失败样本；
- `failed`：任务级错误导致无法继续；
- `cancelled`：被用户取消。

Worker 负责调用现有 `medical-evals` 评测程序，并将任务状态、进度和结果索引持久化。任务创建 API 必须快速返回 `task_id`，不能等待整个评测完成。

重试策略：

- 网络超时、限流、临时 Provider 错误：最多自动重试 3 次；
- 使用递增等待时间；
- 认证失败、参数错误、数据格式错误：不自动重试；
- 保存每个样本的重试次数和最终状态；
- 第一版不支持断点续跑，失败任务需新建任务重跑。

前端通过轮询任务状态 API 获取基础实时进度，至少返回 `completed_count`、`total_count`、`progress_percent`、`status`、`success_count`、`failed_count` 和 `retry_count`。

## 7. 模型与评测配置

平台支持多个 Provider，包括 OpenAI、Anthropic、Google 和 OpenAI-compatible 自定义 Endpoint。每次任务绑定一个被测模型配置和一个独立 Judge Model 配置。

任务必须保存不可变的配置快照：

- Provider 和模型名称/版本；
- Endpoint 标识（不得保存明文 API Key）；
- 被测模型生成参数：temperature、top_p、max_tokens 等；
- Judge Model 和 Judge 参数；
- 数据集 ID 与版本；
- 内置 Rubric ID 与版本；
- 并发、超时、重试配置；
- 代码版本、prompt 版本和创建时间。

API Key 只由后端接收和使用，必须加密或由本机安全配置提供；前端只显示脱敏标识。API Key 不得写入 Registry、JSONL 运行记录、报告或日志。

第一版只使用平台内置 Rubric，不允许管理员修改或创建 Rubric。

## 8. 存储与报告

第一版按单机部署：

```text
Frontend
  ↓ HTTP API
Evaluation API
  ├── SQLite：任务、配置快照、状态、结果索引
  ├── 本地文件：JSON/JSONL 运行记录和报告源文件
  └── 本地任务队列
        ↓
      Worker
        ↓
  medical-evals evaluator
```

存储接口应抽象为 Repository/Storage，队列接口应抽象为 Queue，模型调用应复用现有 CompletionFn/Provider 边界，以便未来迁移到 PostgreSQL、Redis、对象存储和多 Worker。

评测结果和本地文件永久保留，管理员可手动永久删除已完成或失败的任务。删除规则：

- 运行中的任务必须先取消；
- 删除前二次确认；
- 同时删除任务配置、结果文件、运行产物和 PDF/HTML 报告；
- 删除不可恢复；
- 只有管理员可以删除。

每个已完成任务生成一份独立 HTML/PDF 报告。报告包含任务配置摘要、模型/Judge、数据集和 Rubric 版本、指标、错误分类、耗时、Token、成本、失败统计、任务 ID 和生成时间，但遵守题库保护规则。管理员可查看、生成和下载。

## 9. API 边界（MVP）

建议 API 保持资源化和与前端无关的领域模型：

```text
POST   /api/auth/login
GET    /api/me
GET    /api/providers
GET    /api/models
GET    /api/judges
GET    /api/datasets
GET    /api/datasets/{id}/versions
GET    /api/rubrics
POST   /api/evaluations/preflight
POST   /api/evaluations
GET    /api/evaluations
GET    /api/evaluations/{id}
POST   /api/evaluations/{id}/cancel
GET    /api/evaluations/{id}/progress
GET    /api/evaluations/{id}/results
GET    /api/evaluations/{id}/report
POST   /api/evaluations/{id}/report/generate
DELETE /api/evaluations/{id}
```

原始样本接口不作为普通结果接口的一部分。应使用单独的受保护路由，并在服务端按管理员身份校验；第一版暂不记录审计日志，但路由和服务边界不能绕过权限层。

## 10. 前端技术与视觉方向

前端采用独立工程，优先使用 React/Next.js、Tailwind CSS 和 shadcn/ui。视觉定位为“可信的医学评测控制台”：专业、克制、清晰，避免医疗 SaaS 常见的过度渐变、装饰性插画和信息过载。

设计原则：

- 以任务状态和证据层级组织信息，而不是以装饰卡片堆叠信息；
- 使用高对比度状态色区分成功、警告、失败和运行中；
- 结果页优先显示可解释的指标和数据来源；
- 表格和进度区适合高密度桌面使用，同时保证窄屏不产生横向溢出；
- 所有操作有明确 loading、空状态、错误状态和完成反馈；
- 交互动画保持短促，主要用于状态反馈和空间连续性；
- 遵守键盘导航、焦点可见、ARIA 标签、`prefers-reduced-motion` 和最小触控尺寸要求。

## 11. 测试与验收标准

### 产品验收

- 未认证用户不能通过直接调用 API 绕过登录；
- 普通结果接口响应中不存在完整基准题目、答案和 Rubric；
- 创建任务时只能选择一个被测模型；
- Judge Model 独立记录并参与评分链路；
- 页面关闭后任务继续运行，重新进入可以恢复进度；
- 临时错误最多自动重试 3 次，永久错误不重试；
- 完成任务后可生成单任务 HTML/PDF 报告；
- 管理员可以删除已完成/失败任务，运行中任务必须先取消；
- 删除后关联的任务、结果和报告文件均不可访问。

### 技术测试

- API 身份认证测试覆盖管理员和未认证请求的每个受保护端点；
- Worker 状态转换、取消和重试逻辑使用 fake Provider 测试；
- 评测程序通过现有 `medical-evals` CompletionFn 边界调用，不在 API 进程中直接执行长任务；
- 存储、队列和 Provider 使用接口测试，避免绑定未来基础设施；
- 前端使用 Playwright 验证登录、创建任务、进度轮询、结果和权限场景；
- 报告测试确认题库保护字段不会出现在普通报告中，原始样本只通过管理员受保护接口访问。

## 12. 后续范围

暂不纳入第一版：真实注册/邀请、SSO/LDAP、多租户、用户上传数据集、自定义 Rubric、批量模型对比、对比报告、断点续跑、审计日志、计费、自动清理和多节点部署。
