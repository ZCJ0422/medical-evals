# 评测指标与运行产物设计

## 背景

当前 Web 评测结果中的 `pass_rate` 实际承载的是 MedQA 答案准确率，容易让用户误解为“请求或解析通过率”。同时，Web Worker 只保存聚合结果到 SQLite，没有复用旧 CLI 的逐题 JSONL 和运行日志写入链路，导致用户无法检查每道题的原始输出、解析状态和错误原因。

## 目标

1. 将指标语义拆开，明确展示解析成功率与答案准确率。
2. 恢复逐题记录、运行日志和聚合摘要，并在每题完成后立即落盘。
3. 保留现有任务结果接口的兼容性，旧任务不因数据库升级而失效。
4. 原始模型输出只通过管理员权限访问，不混入普通聚合结果。

## 指标定义

- `parse_success_rate`：成功获得模型响应且能解析出合法答案的题数 / 成功获得模型响应的题数。没有可解析响应时为 0；没有完成任何请求时为 `null`。
- `accuracy`：答对题数 / 总题数。解析失败和请求失败均不计为正确，保持当前准确率语义。
- `completed_count`：已完成处理的样本数，包括成功解析、解析失败和请求失败。
- `request_success_count`：模型请求成功返回的样本数。
- `parse_failed_count`：模型请求成功但答案无法解析的样本数。
- `failed_count`：模型请求或评测流程异常的样本数。
- `retry_count`：累计重试次数。

前端不再把准确率称作 `pass_rate`，结果页主指标显示“解析成功率”和“答案准确率”。旧数据库记录没有逐题数据时，解析成功率显示为“不可用”，准确率沿用已保存的旧总分。

## 运行产物

每个任务写入 `backend/data/artifacts/<task_id>/`：

- `samples.jsonl`：逐题记录，完成一题后立即追加并 flush/fsync。
- `run.log`：任务生命周期、进度、异常和汇总日志。
- `summary.json`：最终聚合指标和错误分类。
- `report.html`：现有报告生成流程继续使用。

MedQA 逐题记录至少包含：样本 ID、题目、提示词、预期答案、模型答案、解析结果、解析失败标记、正确性、原始输出、错误和重试次数。HealthBench 记录对应保留回答、rubric 判断、得分和错误信息。

## 后端改造

1. 扩展 `EvaluationRunResult`，携带逐题记录和独立指标。
2. 适配器在每题完成后通过回调交给 Worker，由 Worker 追加写入 `samples.jsonl` 并记录日志。
3. 扩展 `task_results` 保存 `accuracy`、`parse_success_rate`、请求成功数和解析失败数；数据库启动时使用幂等 `ALTER TABLE` 兼容旧库。
4. 结果服务与响应模型改用新字段；在过渡期保留 `total_score` 作为兼容字段，但不再作为前端展示名称。
5. 增加管理员样本记录读取接口，支持分页读取 JSONL，普通结果接口只返回聚合指标。
6. 任务失败或取消时也写入日志和已有摘要，避免只留下空目录。

## 前端改造

1. 结果摘要卡片改为显示解析成功率、答案准确率、请求成功数、解析失败数、请求失败数和重试次数。
2. 对历史任务或没有逐题产物的任务显示“不可用”，不将准确率误标为解析成功率。
3. 增加逐题记录查看入口，支持展示解析状态、正确性、错误和原始输出（管理员页面）。
4. 更新类型、国际化文案、测试夹具和 E2E 断言。

## 验证策略

- 单元测试：MedQA 解析成功/失败、请求异常、准确率与解析成功率分离、旧数据库兼容。
- Worker 测试：逐题 JSONL 实时追加、日志和 summary 生成、取消/失败场景。
- API 测试：新结果字段、旧结果回退、样本分页读取和权限保护。
- 前端类型检查、构建和 E2E：结果页指标名称、历史任务兼容和逐题记录展示。

## 自检结论

该方案解决了两个独立问题：指标名称纠正，以及运行产物恢复。将逐题记录放在任务 artifact 目录而不是全部塞入 SQLite，可保留原始输出并避免数据库膨胀；SQLite 只保存查询结果页所需的聚合字段。JSONL 采用追加写入，任务中断时仍能保留已完成题目，便于诊断和恢复。
